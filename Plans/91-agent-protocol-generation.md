# План 91 — Генерация универсального протокола агента в `onebase ai-guide`

Дата проектирования: 2026-07-26.
Статус: ⬜ Проект → реализуется в этой же ветке (`feature/91-agent-protocol-generation`).

## Мотивация

`onebase ai-guide` генерирует `AGENTS.md` — *справочник* (структура конфигурации,
рабочий цикл, встроенные функции DSL, схема метаданных, безопасность). Отдельно
накопилась *процессная* дисциплина: **какими инструментами доказывать, что
конфигурация реально работает**, а не только что «`onebase check` зелёный». Сейчас
эта дисциплина живёт в рукописном личном файле с захардкоженными путями
(`C:\Project\onebase-1`, `C:\Users\…\go-sdk`) — она непортируема (на другом компе
пути другие) и протухает (движок меняется, файл — нет).

Цель: перенести **универсальную процессную часть** в генератор, чтобы она была
(а) у каждого пользователя из коробки, (б) синхронна версии движка,
(в) **портируема** — без единого машинного пути.

## Принцип: три вида контента

- **static** — стабильная проза без путей (дисциплина проверки, «как доказывать»,
  формат отчёта). Одинакова на любой машине.
- **generated** — из самого движка (таблица команд, грабли запросов, сигнатуры
  builtins). Не устаревает при изменении движка.
- **discovered** — вычисляется в момент генерации на машине пользователя
  (ОС-специфика через `runtime.GOOS`, путь проекта через `--project`). Корректно
  на любом компе именно потому, что не зашито.

Универсальность = static + generated + discovered, **ноль зашитых `C:\…`**.

## Аудитория — разработчик КОНФИГУРАЦИИ

У него `onebase` на PATH и папка проекта; репозитория движка нет и не нужно.
Поэтому в генерируемый протокол **НЕ входит** engine-dev-специфика (сборка бинаря,
`taskkill` залоченного exe, CRLF/`gofmt`) — она остаётся в `CLAUDE.md`
репозитория движка, где пути относительны репо и это уместно.

## Что добавляется в `AGENTS.md`

1. **Секция «Проверка результата (доказательства)»** (static) — сразу после
   «Рабочего цикла», потому что опирается на его инструменты:
   - тезис «зелёный `check` ≠ работает» (`check` ловит компиляцию и
     `no such column/table`, но не бизнес-поведение);
   - что чем доказывать по типу изменения: проведение/движения/остатки →
     `procrun` + `onebase query`, сверить числа; агрегаты → `onebase query`;
     отчёт/виджет → `report explain` / `widget explain --json`; UI/формы →
     `onebase run` + браузер **или честное «UI не проверен headless»**; роли/RLS →
     сессионный прогон под ролью (`ИмяПользователя()` пуст в `procrun`);
   - краткий формат финального отчёта (Tool trace / Сделано / Проверки / Как открыть).
2. **Блок «Окружение (определено при генерации)»** (discovered, опционально) — при
   `--project`: абсолютный путь проекта + ОС-условная заметка о запуске `onebase`.
   Если проект не задан — блок пуст, документ остаётся чисто портируемым.

## Что осознанно ВНЕ движка

- Реестр пробелов ТЗ (`G1–G6`) — специфика конкретного проекта (колл-центр
  ICE-32), а не платформы → руками или будущим скаффолдером.
- Engine-dev workflow (сборка, `taskkill`, CRLF) — в `CLAUDE.md` движка.
- Скаффолдер `onebase new --from-tz` (ТЗ → метаданные + привязка к проекту) —
  отдельная бо́льшая задача (стык с ИИ-помощником, планы 48/51), отдельный план.

## Изменения в коде

- `internal/cli/aiguide.go`:
  - новая static-секция «Проверка результата (доказательства)» в теле руководства;
  - сигнатура `generateAIGuide(envBlock string)` — принимает discovered-блок и
    вставляет его после вводного абзаца (пустая строка → ничего не добавляет);
  - `environmentNote(projectDir string) string` — discovered-блок с
    `runtime.GOOS`-условной заметкой; `""` при пустом `projectDir`;
  - флаг `--project` у `ai-guide`; `runAIGuide` вычисляет `environmentNote`.
- `internal/cli/init.go`: `writeAIGuide(dir)` передаёт `environmentNote(dir)`
  (у скаффолда есть каталог проекта → блок «Окружение» попадёт в его `AGENTS.md`).
- `internal/cli/aiguide_test.go`: новая сигнатура; проверка новой секции и якорей
  доказательств; проверка `environmentNote` (пустой случай + GOOS-условность).

## Тесты

- guide содержит «## Проверка результата» и якоря (`procrun`, «не проверен headless»);
- `environmentNote("")` == `""` — портируемость по умолчанию;
- `environmentNote(dir)` содержит путь проекта и на текущей ОС — соответствующую
  ОС-заметку;
- существующий `TestGenerateAIGuide_HasSignaturesAndSections` продолжает проходить.

## Verification

```bash
go test ./internal/cli/
onebase ai-guide                      # портируемый вывод, без машинных путей
onebase ai-guide --project examples/trade   # + блок «Окружение» с путём и ОС-заметкой
```
